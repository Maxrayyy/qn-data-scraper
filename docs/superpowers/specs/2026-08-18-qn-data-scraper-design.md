# 千牛数据抓取工具（qn-data-scraper）设计文档

日期：2026-08-18
状态：已与用户确认（方案 A+A+B）

## 1. 背景与目标

淘宝千牛卖家中心（qn.taobao.com）的"数据 → 市场 → 类目洞察 → 价格分析"页面提供类目下商品的"商品发现"数据（商品图、商品名、商品id、支付单量、件单价），需要人工逐条点击"商品发现"按钮、手动复制弹窗数据到 Excel。本工具将全流程自动化：

- 普通用户（无编程能力）只需输入网址、账号、密码、导出路径，点击【开始执行】即可；
- 内置步骤自动完成：登录 → 导航到价格分析页 → 切换类目"猫笼子/猫别墅" → 遍历"分析明细"逐条点开"商品发现"弹窗 → 抓取弹窗列表 → 导出 Excel；
- 最终交付 Windows exe（云端 GitHub Actions 构建），目标电脑**不需要安装 Python/浏览器/任何环境**；
- 全程本地运行，账号密码与抓取数据**禁止任何网络上传**。

## 2. 技术选型（已确认）

| 决策点 | 选择 | 理由 |
|---|---|---|
| GUI | PySide6 | 稳定成熟，Qt 信号天然适合跨线程刷日志 |
| 浏览器自动化 | Playwright（Python） | 内置 Chromium 可随 exe 打包 |
| 线程模型 | **异步 API + 后台线程 asyncio 事件循环** | 停止任务时线程安全关闭浏览器，不残留进程（同步 API 跨线程强杀不稳定） |
| 打包形态 | **PyInstaller onedir 单文件夹**（Chromium 内置 `browsers/` 目录） | 秒启动；onefile 每次启动解压 250MB 体验差 |
| exe 构建途径 | **GitHub Actions 云端 Windows 构建**（用户有 GitHub 账号）+ build.bat 本地备用 | 开发机为 macOS，PyInstaller 无法跨平台编译 |
| Excel | openpyxl | 支持嵌入图片 + 单元格超链接 |
| 验证码 | 不自动处理，检测到即暂停等人工 | 规格要求；千牛滑块验证高频出现属预期 |

## 3. 项目结构

```
qn-data-scraper/
├── main.py                      # 程序入口（创建GUI）
├── app/
│   ├── gui.py                   # PySide6 界面：表单、按钮、日志区
│   ├── worker.py                # 后台线程：asyncio事件循环 + 停止信号
│   ├── steps.py                 # ★★ 内置操作步骤（开发者唯一需要改的文件）
│   ├── scraper.py               # 弹窗列表数据提取（纯逻辑，可单测）
│   ├── excel_export.py          # Excel 导出（嵌入图片+超链接+时间戳重名）
│   ├── config.py                # 配置读写 + 密码简单加密
│   └── captcha.py               # 验证码检测与"暂停等人工处理"逻辑
├── tests/                       # 纯逻辑单元测试（提取/导出/配置）
├── requirements.txt             # 锁定版本依赖
├── scraper.spec                 # PyInstaller 打包配置（内置浏览器）
├── build.bat                    # Windows 本地一键打包（备用）
├── .github/workflows/build-exe.yml  # 云端自动构建exe
└── README.md                    # 用户使用说明 + 开发者文档
```

## 4. 核心数据流

```
[GUI表单] → 校验输入 → [Worker后台线程]
                         │ 启动 asyncio + Playwright Chromium（有头模式，用户可见）
                         │ 依次执行 steps.py 内置步骤，每步写中文日志→GUI日志框
                         │ 遇验证码 → captcha.py 检测 → 日志提示→暂停轮询等人工处理
                         ▼
                 [弹窗数据提取 scraper.py]
                         │ 图片通过浏览器会话 context.request 下载到临时目录
                         ▼
                 [excel_export.py 生成xlsx] → 日志"导出成功，共N条，路径xxx"
[停止任务按钮] → 线程安全关闭浏览器 → 清理chromium残留进程 → 日志"任务已停止"
```

- 自动化全程跑在**后台线程**，GUI 永不卡死；日志通过 Qt 信号安全刷到界面。
- 浏览器**有头模式**（用户可见操作过程），验证码出现时用户在浏览器窗口手动完成，工具检测验证码消失后自动继续。

## 5. 内置操作步骤（steps.py，9 步）

每步 = 一个函数，带中文日志、超时、失败重试 2 次、验证码检测。类目名"猫笼子/猫别墅"作为常量放在文件顶部。

| 步骤 | 动作 | 定位方式（多级回退） |
|---|---|---|
| 1 | 打开千牛登录页（URL 从表单读） | — |
| 2 | 点"密码登录"页签 → 填账号（主账号:子账号格式）→ 填密码 → 点登录 | `#fm-login-id` / `#fm-login-password` + placeholder 文本回退；滑块验证→暂停人工 |
| 3 | 等待登录成功跳转 qn.taobao.com 工作台 | URL 变化 + 页面出现标志元素 |
| 4 | 点左侧栏"数据" | `text=数据` + 图标类名回退 |
| 5 | 点上方栏"市场" | `text=市场` + 回退 |
| 6 | 点左侧栏"类目洞察" | `text=类目洞察` + 回退 |
| 7 | 点"价格分析" | `text=价格分析` + 回退 |
| 8 | 点类目切换区 → 输入类目名 → 点搜索结果对应类目 | 输入框 + 下拉结果文本匹配 |
| 9 | 遍历"分析明细"每一行 → 点"商品发现" → 弹窗内滚动加载全量列表 → 提取数据 → 关弹窗 → 下一行 | `text=商品发现` 逐行定位；弹窗内滚动到底直至无新增 |

每步之间统一执行验证码检测（淘宝滑块/无痕验证元素）；检测到后暂停等待人工处理，默认最多等 10 分钟（代码常量可调）。

## 6. 数据抓取与 Excel 导出

**抓取**（scraper.py，纯逻辑、不依赖浏览器，可单元测试）：
- 弹窗内列表逐项提取 5 字段：商品图（img src）、商品名（a 标签文字）、商品id（从商品链接 URL 正则提取）、支付单量、件单价；
- 图片通过浏览器会话 `context.request` 下载（复用 Cookie + 带 Referer 头，规避淘宝 CDN 防盗链），存入临时目录，导出后清理；
- 商品id 提取失败时回退从图片 URL 提取；仍失败留空并在日志提示。

**Excel 导出**（excel_export.py）：
- 表头 5 列：`商品图片 | 商品名 | 商品id | 支付单量 | 件单价`；
- 图片以真实图片嵌入（缩略约 60px 高、行高自适应）；商品名单元格带超链接；
- 多条"商品发现"数据依次追加到同一个 xlsx；重名文件自动追加时间戳（`xxx_20260818_153012.xlsx`），绝不覆盖；
- 中途停止任务时，已抓到的数据尽力导出。

## 7. 异常容错与停止语义

- 每一步独立 try/except：超时/元素找不到/点击失败 → 中文日志"第 N 步失败：找不到"XX"按钮，原因：……"→ 重试 2 次 → 仍失败则结束任务并弹窗提示，**不崩溃**；
- 全局兜底异常捕获，日志打印完整错误，GUI 不闪退；
- 登录失败判断：登录页残留/密码错误提示文字 → 明确中文提示；
- 【停止任务】：Qt 信号跨线程关闭浏览器 context → 按 PID 精确清理 chromium 子进程树（不动用户自装 Chrome）→ 日志"任务已停止，浏览器已关闭"；
- 窗口关闭（点 X）同样走完整清理，不留后台残留进程。

## 9. 配置与密码加密（config.py）

- 【保存配置】写入 Windows 用户目录 `%APPDATA%\qn-data-scraper\config.json`（若该目录不可写，回退到 exe 所在目录）：URL、账号、导出路径、超时秒数、加密后的密码；
- 加密：基于机器特征派生密钥的 XOR + Base64 混淆（规格要求"简单加密"；代码注释明确标注**非强加密**，仅防明文裸存）；
- 配置只读写本地文件；代码中不存在任何网络上传逻辑；密码不写日志。

## 10. 打包与云端构建

- **PyInstaller onedir + `--noconsole`**：Chromium 内置在 `browsers/`（运行时设 `PLAYWRIGHT_BROWSERS_PATH` 指向），用户电脑无需安装浏览器/环境；交付 zip，解压双击 exe 运行；
- **GitHub Actions**（`.github/workflows/build-exe.yml`）：推送代码 → windows-latest 云端装依赖 + `playwright install chromium` + PyInstaller 打包 + 上传产物 → 用户在仓库 Actions 页面下载；
- **build.bat 备用**：任意 Windows 电脑双击自动完成本地打包；
- 打包步骤与常见坑（如 node 驱动缺失、浏览器路径）写入 README 开发者章节。

## 11. 测试策略与已知风险

**测试**（开发机为 macOS，无法真机登录淘宝）：
- 纯逻辑单元测试（本地可跑）：表格/弹窗数据提取（HTML fixture）、Excel 导出（图片嵌入、时间戳重名）、配置加密往返；
- README 附"手动冒烟测试清单"：Windows 上拿到 exe 后按清单走真实流程验证。

**已知风险（如实告知）**：
1. 淘宝登录页/千牛页面元素改版 → 所有定位器集中在 `steps.py` 一处，改版后开发者只改这一个文件；
2. 千牛登录可能频繁触发滑块验证 → 工具暂停人工滑一次，属预期行为；
3. 淘宝可能对自动化环境有风控 → 有头模式 + 手动验证已尽量降低；若登录被风控拦截，日志明确提示；
4. 首次云端构建可能需要微调打包配置，常见坑的解决办法写入文档。
